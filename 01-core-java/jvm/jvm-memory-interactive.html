Sample Program

bytecode becomes runtime state 
class Account {
  private String owner;
  private int balance;

  Account(String owner, int balance) {
    this.owner = owner;
    this.balance = balance;
  }

  void deposit(int amount) {
    balance = balance + amount;
  }
}

public class DemoApp {
  public static void main(String[] args) {
    Account a = new Account("Riya", 100);
    a.deposit(50);
    int[] checkpoints = {100, 150};
    System.out.println(a);
  }
}

Step 1 of 8 Compile
    Region Shared or private What lives there How it links to other regions Common failure
    Heap Shared by all threads Objects, arrays, many string objects Stack local variables hold references to heap objects; object headers point to class metadata. OutOfMemoryError: Java heap space
    JVM Stack Private per thread Method frames, local variables, operand stack, return information Frames contain primitive values and references to heap objects; PC register points at the frame's executing instruction. StackOverflowError
    Method Area / Metaspace Shared by all threads Class metadata, method metadata, field metadata, runtime constant pool ClassLoader loads metadata here; heap objects know their class through metadata; bytecode execution reads method info. OutOfMemoryError: Metaspace
    PC Register Private per thread Current bytecode instruction address Lets the JVM resume the right instruction after scheduling, method calls, branches, or exceptions. Usually JVM managed; undefined during native method execution.
    Native Method Stack Private per thread in many JVMs Native method frames used by JNI and VM internals Used when Java code calls native code, such as low-level I/O, OS, or library operations. OutOfMemoryError or stack-related native failure
